# Field-Guided Execution — the operating pattern

**Locked 2026-08-07, from the pollution purge that proved it.** This is the
procedure for any destructive or state-changing operation on the substrate.
It is not advice; it is the shape the successful operation actually took,
recorded so the next one takes it too.

## The arc

1. **Write the plan as an artifact.** Exact targets, invariants, and the
   method questions you cannot yet answer. A plan you cannot goggle is not
   a plan.
2. **Compress the plan into the field before executing anything.** Goggle
   it. The plan becomes a reading: FOCUS, META resonances, FIELD reaction,
   traps fired against it.
3. **Follow the resonance.** The nearest structural siblings are the
   instrument pointing at doctrine and precedent. In the proving run, a
   purge plan's top resonance was `void/FIELD-SELF-COMPRESSION.md` (0.960)
   — the system's own document on operating on field memory — and the traps
   prescribed the audit verb and the seeds/ placement unprompted.
4. **Let the capability surface answer the method questions.** The goggles
   list what the neighborhood can already do (`--do call` makes it
   runnable). The proving run found `deletePatternById` — transactional,
   archive-first, audit-logged — instead of inventing a deletion.
5. **A missing verb is a finding, never a license.** If no lawful operation
   exists (the engine had nothing between `reset()` and hand-editing
   state), BUILD the narrow verb: exact arguments, mandatory reason,
   invariants enforced, and the operation records itself in the state it
   changes. The purge built `pruneSources` — the field remembers its own
   cleaning in `sourcesPruned`.
6. **Execute through the one surface.** The proving run ran the prune via
   `goggles --do call …#pruneFieldSources`, not via a side script.
7. **Verify as adversary, not author.** The verify step caught the new
   verb's own defect (the load path dropped the pruning ledger — a silent
   edit in disguise) before the on-disk record was overwritten.
8. **Expect to be caught, and let the catches stand.** Two gates blocked
   the proving run's commits (size ratchet, twice adjudicated FPs). Every
   catch resolves code-side and lands in `seeds/catches.seed.json`. The
   gate never moves.

## Invariants (every run)

- History is never rewritten: integrals, update counts, archives, and git
  are append-only records. Cleaning removes labels, not memory.
- Exact targets only. No wildcard destructive operation exists, anywhere.
- Every removal is logged where it happened AND in the commit message.
- The plan, the readings, and the receipts survive the operation.

## Why this is the pattern and not a checklist

Each step consumes the previous step's *measurement*: the plan is planned
against what the field already holds, the method is chosen from what the
substrate already knows how to do, and the verification distrusts the very
thing just built. That is the loop (compress → place → react → govern →
remember) applied to an OPERATION instead of an artifact — the system
using itself to change itself, with the record to prove it.
